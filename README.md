# 无名剧场

SillyTavern 扩展 · **0.6.1** · 作者 **Zeya**。
在奶油纸雕剧场里开始创作，写完后展开独立阅读页，支持编辑、保存、收藏与续写。生成与续写均不自动写入聊天。

四个主栏目分别负责开始创作、挑选剧目、阅读作品和默认设置；桌面与手机都保留主导航，故事在独立阅读页展开。

## 安装与更新

需要 SillyTavern 1.14.0 或更新版本，以及已配置的模型连接。

**首次安装：**打开酒馆「扩展 → 安装扩展」，粘贴下面的仓库地址，安装完成后刷新酒馆：

```text
https://github.com/jiuyi777/interlude-theatre
```

**从仓库更新：**在扩展管理中找到「无名剧场」，检查并安装更新，然后刷新酒馆。本插件不会自动更新。刷新会中断正在生成的内容，请先完成当前创作。

**使用压缩包：**从 [0.6.1 下载页](https://github.com/jiuyi777/interlude-theatre/releases/tag/v0.6.1) 下载 `interlude-theatre-0.6.1.zip`，将其中的 `interlude-theatre` 文件夹放到 `SillyTavern/public/scripts/extensions/third-party/`。确认 `manifest.json` 位于插件第一层，然后刷新酒馆。通过压缩包安装的版本，再次下载新版覆盖更新；替换文件前保留原插件目录。

打开聊天输入框旁的「剧场」，或扩展菜单中的「无名剧场」。有些酒馆主题没有输入框快捷入口，可以使用扩展菜单。

## 使用

1. 从「剧场大厅」选择「从剧目库开始」或「写下自己的故事」。剧目库中点「用这个剧目」，进入填写要求的页面。
2. 填写故事标题和想发生的情节，点「开始写故事」。勾选「发送全部聊天上下文」后，提供当前主聊天的全部正文；角色资料不再截断。启用的预设、关联世界书中的开启条目及当前扩展注入提示也会提供。关闭复选框只省略主聊天正文，仍保留人物与世界资料。请求发送到酒馆已配置的模型，消耗该服务额度。
3. 写完自动展开独立阅读页，顶部只有返回、必要的篇章选择与编辑按钮。AI 自己设计正文配色和版式，使用完整可用空间。点「编辑正文」修改，点「保存并阅读」返回阅读；编辑草稿会自动暂存到本机。
4. 「演出记录」集中保存写完的故事，点「打开阅读」找回正文。阅读页可收藏故事，记录页可筛选收藏；剧目库中的收藏代表创作模板。
5. 阅读页点「续写下一篇」，填写后续情节。新篇章追加在原故事之后；上方篇章选择可切换阅读、编辑。续写需要原角色聊天，并提供全部前篇正文；超出模型容量时须调整模型容量或发送范围。「更多 → 按原要求另写一版」则创建另一部故事，旧作品保留。
6. 如需进入主聊天，在阅读页「更多」中核对聊天目标，再点「写入聊天」。以正文文字新增一条角色消息，不自动触发模型。相同作品版本在同一聊天只写一次，成功后显示「已写入此聊天」。修改正文并保存后可以手动写入新版本。
7. 阅读页「更多 → 下载整部故事」导出全部篇章的离线 HTML；「演出记录 → 备份与恢复」导出、导入可恢复的 JSON。导入作为新副本，原作品保留。「导演室」设置以后新故事的默认写法。

## 保存在哪里

作品全文、收藏和编辑草稿保存在**当前浏览器、当前酒馆站点的 IndexedDB**；不是云端同步。作品按酒馆扩展设置中的库标识隔离。浏览器清理站点数据、无痕窗口关闭或浏览器自动回收存储都可能移除本机作品，请保留导出的备份。

新版不再按 100 条或 200 万字符裁剪正文。容量不足时明确提示，仍可查看或下载当次生成的内容。旧版演出记录会复制入新作品库，原扩展设置不删；旧版已经裁掉的正文无法恢复。旧版设置中的库标识尚未同步到酒馆服务器时，请避免立即强制刷新。

写入聊天后，插件调用宿主保存，并读取指定聊天核验作品标记。若未核实保存，界面提示重试；同一条已显示消息不会再次新增。作品导入为副本时不继承已发送标记。

## 视觉与内容规则

保留奶油纸雕剧场、纸页花纹和插画封面。背景移除固定在大厅上的选中箭头与星星，当前栏目由实际页面状态显示。创作与管理内容放在纸页空白区，完成的故事使用独立阅读页；窄屏保留四个主栏目与正常字号。

AI 的 HTML/CSS 决定正文的背景、字体、宽度与留白。阅读器只提供低优先级基础样式和隔离边界，不再强制套用大厅的奶油纸色、固定宽度或大标题。

内置剧目、导入剧目、自写故事和续写共用 `visual-guidance.js` 中的阅读设计要求。规则约束配色职责、中文排印、信息层级和手机阅读；具体的视觉载体、明暗冷暖、章节结构与细节由 AI 依据本篇内容决定。没有按剧目名称或 ID 分配固定皮肤，聊天、百科和信件只是开放示例。改进规则后，新生成内容采用新规则，已保存的作品保持原样。

美化要求以 **D0（最后一条 system 消息）** 放在本次生成请求末尾，顺序为完整资料与主聊天 → 本次创作要求及全部前篇、续写要求 → 阅读设计与输出要求。插件通过 `generateRaw` 自己传入有序消息，不写入全局注入区；美化关闭时，末尾只保留简洁阅读与 HTML 交付规则。新版设计指导要求将内容母题落实为构图、材质与至少两处叙事细节，避免仅给普通阅读框换色。

界面、嵌套阅读框与下载 HTML 均隐藏滚动条外观，保留滚轮、触摸与键盘滚动。文字与标题无下划线和底部装饰线。生成文档在无脚本的隔离框架内展示，仅支持 HTML/CSS 与原生展开交互，外部资源和表单会被移除。

## 剧目导入

「剧目库 → 导入剧目簿」支持导入单个 JSON、数组、`{"scripts": [...]}` 和带 `entries` 的世界书合集，先预览再收录。最小格式：

```json
{"title":"雨夜来信","description":"把旧日误会说清，写完一个温暖的结局。","prompt":"让 {{char}} 与 {{user}} 收到旧信，根据人物设定写完故事。"}
```

## 常见问题

- 找不到入口：确认插件目录没有多套一层，刷新酒馆，再打开扩展菜单。
- 生成失败：先确认酒馆本身可以正常回复。空响应不会覆盖已有作品。刷新网页会中断尚未完成的请求；关闭剧场面板不会中断。
- 无法保存作品：保持页面打开，先下载 HTML 或导出作品备份，再检查浏览器存储空间。
- 换设备后找不到作品：在原浏览器导出作品备份，再到新设备导入。
- 写入提示聊天已切换：检查新目标后再次点击。插件不会自行跳转或选择聊天。
- 本地预览不能生成：普通 `preview.html` 是离线界面预览，会明确提示需要模型连接；它不再用固定故事冒充生成结果。真实酒馆使用已配置的模型。

## 完整上下文范围

- 人物：当前角色资料、开场白、备选开场白、示例对话与 Persona，取消原来的 24000 字符截断。
- 聊天：当前主聊天全部正文，取消只取预算内最近消息和裁剪长消息的规则。插件曾写入的番外及旧版剧场指令仍隔离，避免混入主线。
- 资料：当前启用且适用于独立生成的预设提示，关联世界书中全部开启条目，以及当前有效的扩展提示。世界书按完整资料发送，不按关键词激活和旧预算裁减；关闭的条目不发送。
- 续写：全部已保存篇章的正文和本次续写要求，包含用户保存的编辑。

插件不再用字符估算悄悄裁切资料。模型自身的上下文及输出上限仍然适用；超限须切换更大容量模型或调整发送范围。附件原文件、其他聊天及未启用资料不属于当前正文上下文。独立生成会沿用酒馆当前连接的输出上限；长故事须为输出留足容量。

## 本地 DeepSeek 验证（2026-10-03）

按“修改通用提示词 → DeepSeek 真实生成 → 查看桌面和手机效果 → 继续修改提示词”完成一轮实际迭代。本轮调用 10 次：4 次 `deepseek-flash`、6 次 `deepseek-v4-pro`，包括最后一次由 Pro 修正剧情数值。其中 2 次 Pro 输出达到上限，插件拒绝把半截 HTML 保存成完整作品；其他已有作品保留。没有手工修改生成页面的颜色、样式或正文来冒充模型效果。

最终三份样本共用 `prompt-v6`，由 `deepseek-v4-pro` 生成，最大输出 16384 tokens，均正常结束（`stop`）：

- 「是网你给我连好了呀」：90 条手机聊天，17px 气泡正文，手机首条消息距阅读文档顶部约 141px。
- 「15天的废物超能力」：完整第 1—15 天与结尾，浅色章节排版，18px 叙事正文。
- 「末班电台」：深色连续叙事与电台细节，17px 正文，完整结束。

三份在 390×844 预览中均无横向溢出，滚动条隐藏，键盘可滚动至结尾；已保存、重开并验证刷新恢复，主聊天仍为 2 条虚构消息。另保存阅读器实际展示的独立 HTML 与截图。桌面操作栏保持 52px，阅读空间由模型设计使用。真实酒馆和手机真机尚未验收，本地修订未发布到 GitHub。

迭代发现 Flash 对身份标注、重复说明与配色指导执行不稳定；Pro 也曾无限扩写聊天。当前提示要求先规划有限数量、完成结局，并明确内容决定设计、清楚的说话者、可读字号与紧凑首屏。`prompts/通用美化提示词.txt` 是从 `buildVisualGuidance('static')` 导出的可读副本，实际请求使用 `visual-guidance.js`，内置、导入、自写与续写共用。酒馆运行时采用用户当前选择的模型和输出上限。

十五天样本原先存在最后一次治疗前血量与结局不衔接的问题。将完整原文交给 DeepSeek 局部修订后，核对返回结果仅改动三处数值，全部 CSS 保持原样，第 1—15 天和结局完整，最终血量按 90 + 10 = 100 衔接。修订版通过故事备份导入保存，原作品保留；已重新打开并验证刷新恢复，独立 HTML 已同步更新。通用创作要求也补充了当前数值、目标差额及各步变化的核对规则。

验证边界：这是三个题材的真实模型输出与本地阅读呈现验证，不代表任意题材均能稳定满足所有要求，也不代表全部剧情细节已经完成内容审校。真实酒馆、手机真机及发布后的体验尚未验收。

## D0 与更鲜明的阅读设计（2026-10-03）

本轮再调用 `deepseek-v4-pro` 5 次：3 次完整生成、2 次依据浏览器实测结果进行局部排版修订。每次实际发给 DeepSeek 的请求均确认最后一条为 system，美化指导只出现一次，所有请求正常结束（`stop`）。前三次正常创作的顺序为 `system → user → assistant → user → system`；后两次把原模型完整 HTML 作为修订依据，通用指导仍位于 D0。

最终展示保留模型生成的调频刻度、雨夜纹理、暖金色细节、来电内容与车票呈现，由 DS 自己收紧手机与桌面的篇头。两次局部修订前后的全部可见故事文字一致；没有人工修改生成 CSS 或正文。最终版已导入演出记录，旧版本保留，另存独立 HTML 与桌面、手机截图。

通用提示采用手机基础 CSS、宽屏增强的设计顺序，要求篇头装饰脱离高度计算，并把构图、材质和剧情细节结合；未加入按剧目标题选择皮肤的分支。390px 手机无横向溢出，剧情引子距文档顶约 91px、字号 17px，正文 17px，滚动条隐藏且可滚动至结尾；1280px 桌面的首段长正文距文档顶约 228px、字号 18px，首屏可完整阅读。刷新恢复另经本地预览检查。

请求顺序与完整上下文的回归检查通过，manifest 检查通过。现有通用能力预检没有通过：2026-08-31 的旧快照缺少 IndexedDB，且该校验器不接受现有 contract 中的 browser 归属。这是旧预检资料与校验器的覆盖缺口；本轮没有修改宿主能力或部署到真实酒馆，不能将本地持久化验证当成目标酒馆能力验收。本轮修改仍未发布到 GitHub。

## 已撤回的状态栏质感实验（2026-10-05—06）

此实验被用户否定，0.6.1 已从实验前备份恢复 `prompt-v8` 的阅读设计方向，并同步恢复可读提示副本。下面仅记录实验过程，不作为当前默认视觉方案。

实验时通用 D0 提示曾更新为 `prompt-v10-d0-artwork`。重点从阅读排版扩展为由模型绘制具体物件、安排图文构图和材质层次，同时加入禁止左侧强调色条配同色填充底块、紧凑篇头和保留手机视觉身份的规则。内置、导入、自写与续篇使用同一个 `buildVisualGuidance`，不按剧目标题绑定皮肤。
